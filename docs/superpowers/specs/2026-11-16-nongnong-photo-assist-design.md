# 농농이 사진 인식 상담 설계

작성일: 2026-11-16 · 대상 브랜치: `feat/nongnong-claude-agent` (PR #25)

## 1. 의도와 이유

농기계를 잘 모르는 초보 농부와 시니어가 기계 이름이나 용어를 몰라도 **사진 한 장과 쉬운 질문**으로 도움을 받게 한다.

사용자는 두 종류다.

- **1 = 구매자·대여받는 사람:** 사진을 올리고 묻는다. "이게 뭐예요?", "시동이 안 걸려요", "이 녹 괜찮아요?" 같은 질문이다. 수리 질문에는 초보도 안전하게 해 볼 수 있는 점검을 단계별로 먼저 안내한다. 그래도 안 되면 근처 수리센터의 전화번호나 사이트로 연결한다.
- **2 = 판매자·대여해 주는 사람:** 사진을 올리면 판매인지 대여인지에 따라 가격을 추천하고, 실제로 쓸 수 있는 소개글을 써 준다.
- **보험:** 1이나 2가 요청할 때만 추천한다.

## 2. 목표 · 비목표 · 반목표

**목표**

- 사진 1장과 질문으로 기종을 알아보고 상태를 짚은 뒤, 질문에 맞는 답을 한다. 사진을 보낸 뒤에도 같은 대화에서 이어 물을 수 있다.
- 수리 질문은 ① 안전한 자가점검 단계 → ② "여기서 멈추세요" 조건 → ③ 수리센터 연결(전화 버튼과 사이트 버튼) 순서로 답한다.
- 판매·대여용 사진에는 참고 가격 범위와 근거, 그리고 바로 쓸 수 있는 소개글을 준다. 사진은 서버에 저장하고, 「이 내용으로 매물 등록하기」 버튼으로 매물 등록 화면을 미리 채워 연다.
- 보험은 사용자가 요청할 때만 상품 개요, 대상, 가입처를 안내한다.
- 답변 데이터는 출처와 확인일이 붙은 **검증 지식 데이터(A안)**에서 가져온다. 웹 검색(B안)은 설정으로 켤 수 있다.

**비목표 (이번에 하지 않음)**

- 매물 자동 등록. 등록 화면은 미리 채워 주지만, 등록 버튼은 사용자가 직접 누른다.
- 보험 가입 대행과 보험료 확정 산정. 기획서(PRD)에서도 자동 보험 가입은 범위 밖이다.
- 1(구매자·대여받는 사람)의 수리·문의용 사진을 저장하는 것.
- 상태(좋음·보통·수리 필요)에 따른 가격 보정, 사진 상담 전용 호출 제한.
- 수리센터 예약이나 접수 대행.

**반목표 (기능이 동작해도 이렇게 되면 실패)**

- 초보에게 위험한 수리를 안내하는 것. 연료·유압 계통 분해, 회전부에 손 넣기, 고압 분무 노즐 직접 점검, 엔진이 켜진 상태의 정비 같은 것이다.
- 지어낸 전화번호, 사이트, 보험 상품을 사실처럼 알려 주는 것.
- 사진만 보고 고장 원인이나 기계 모델을 단정하는 것. 사진 판단은 언제나 "추정"으로 표시한다.
- 보험 가입을 권유하거나 사용자가 묻지 않았는데 보험을 꺼내는 것.
- 1의 사진이나 개인정보가 로그·저장소에 남는 것. 2의 판매·대여용 사진도 로그인한 본인의 매물 초안으로만 저장한다.

## 3. 제약

- **서비스 지역:** 경북 영양군 4개 읍면(영양읍, 청기면, 입암면, 수비면). "근처 수리센터"는 이 지역 기관과 전국 제조사 A/S 창구를 뜻한다.
- **기종:** 카탈로그 실제 모델 12종과 기종 13종. 카탈로그 밖의 기계는 기종 수준까지만 안내한다.
- **매물 가격:** 시연 데이터다. 가격 추천은 반드시 "플랫폼 등록 매물 기준 참고가"로 표시하고 시세라고 부르지 않는다.
- **AI 공급자:** Z.ai와 Anthropic(`server/llm.js`). Z.ai 글 상담은 `glm-5.3`, 사진이 있는 호출은 `glm-5.3-flash`(이미지 입력을 기본 지원)를 쓴다. Claude는 같은 모델로 이미지를 처리한다.
- **이미지 크기:** 업로드 검증 상한은 1MB(`server/images.js`). 클라이언트에서 긴 변 1280px JPEG로 줄여서 보낸다.
- **호출 제한:** 사진 상담도 기존 `recommend` 한도를 같이 쓴다. 별도 한도는 두지 않는다.

## 4. 고려한 방법

1. **기존 `/api/agent` 확장 (선택)**: 사진을 대화에 첨부하고 도구를 추가한다. 후속 질문이 자연스럽고, 승인 카드·선택지·공급자 전환을 재사용한다.
2. **사진 전용 API·화면**: 단순하지만 대화가 끊긴다. 시니어에게는 화면이 둘이라 혼란스럽다.
3. **기종 분류만 AI, 나머지는 규칙**: 가장 예측 가능하지만 자유 질문에 답하지 못하고 소개글이 틀에 박힌다.

사용자가 방법은 맡겼고, 후속 질문과 재사용성 때문에 1을 골랐다.

## 5. 사용자가 정한 것

- 사용자 유형 1·2와 각 유형의 기능(위 1절)
- 수리: 안전한 자가점검 먼저 → 안 되면 수리센터 전화·사이트 연결
- 판매·대여용 사진은 서버에 저장한다(소개글과 매물 등록에 쓰기 위해)
- 「이 내용으로 매물 등록하기」 버튼으로 등록 화면을 미리 채워 연다(B안)
- 가격 상태 보정과 사진 전용 호출 제한은 하지 않는다
- 보험은 요청 시에만
- 데이터: A안(검증 지식 데이터) 기본, B안(웹 검색)은 켤 수 있게
- Z.ai 모델은 5.3 계열
- 반영 위치: 농농이 PR 브랜치

## 6. 설계

### 6.1 화면 (채팅창)

```
┌ 농농이 · AI 농기계 상담사 ─────────────┐
│ [사진 미리보기 ✕]                      │
│ ┌──────────────────────────┐ [📷][전송] │
│ │ 예: 시동이 안 걸려요     │            │
│ └──────────────────────────┘            │
└────────────────────────────────────────┘
```

- 📷 버튼으로 사진 1장을 고른다(휴대폰에서는 카메라 촬영 가능). 입력창 위에 미리보기와 삭제 버튼이 보인다. 사진만 보내도 된다.
- 내가 보낸 말풍선에는 사진 썸네일이 보인다.
- 농농이 답변은 "한 줄 결론 → 번호 붙은 단계 → ⚠️ 안전 주의" 순서다.
- 수리센터는 카드로 보여 준다. 카드에는 기관명, 무엇을 하는 곳인지, `📞 전화하기`(tel: 링크) 버튼, `🌐 사이트` 버튼, 확인일이 들어간다.
- 판매·대여 답변은 카드로 보여 준다. 카드에는 저장된 사진, 제목, 참고가("○○~○○원, 근거: 비슷한 매물 N건"), 소개글, `📋 소개글 복사` 버튼, **`📝 이 내용으로 매물 등록하기`** 버튼이 들어간다.
- 등록하기 버튼을 누르면 기존 매물 등록 화면이 열린다. 사진, 제목, 소개글, 거래 방식(판매/대여), 추천 가격(중앙값), 기종·모델(인식된 경우)이 미리 채워진다. 사용자가 확인하고 고친 뒤 '등록'을 누른다. 로그인하지 않았으면 로그인 후 이어서 연다(기존 `savePendingIntentAndRedirectLogin` 방식).
- 글자와 버튼은 기존 채팅 스타일을 따르되, 버튼 높이는 44px 이상이다.

### 6.2 요청 흐름

1. 클라이언트가 사진을 줄여서 `data:image/jpeg;base64,...` 형태로 `/api/agent`(`action: "chat"`)에 `image`와 함께 보낸다.
2. 서버는 `decodePhotoDataUrl`과 `validateAndReencodeImage`(EXIF 제거, 재인코딩)로 검사한다. 이 단계에서는 저장하지 않는다.
3. 그 메시지만 이미지 블록을 붙여 모델에 보낸다. 대화 기록(클라이언트가 보관)에는 사진 대신 `[사진 첨부]`와, 모델이 `note_photo` 도구로 남긴 **사진 인식 요약**만 남긴다. 그래서 후속 질문 때 사진을 다시 보내지 않는다.
4. 응답에 새로 담는 것: `repairCenters`(카드용), `listingDraft`(제목·소개글·가격·거래 방식·기종·모델·사진 키), `photoSummary`(기록용), `sources`(근거 링크).
5. **사진 저장(2의 판매·대여일 때만):** 모델이 `prepare_listing_draft` 도구를 부르면 서버가 저장한다.
   - 서버가 새 매물 ID(UUID)를 만들고, 재인코딩한 사진을 기존 저장소에 `listings/<새 매물 ID>/<uuid>.webp` 키로 저장한다(`putPhotoObject`, 기존 키 형식 그대로).
   - 로그인이 필요하다. 로그인하지 않았으면 저장하지 않고 초안만 돌려준 뒤, 등록하기를 누를 때 로그인으로 보낸다. 사진은 브라우저가 들고 있다가 로그인 후 등록 화면에서 다시 올린다.
   - 같은 대화에서 다시 저장하지 않도록, 저장된 키를 응답과 대화 기록에 남긴다.
6. **등록:** `createListing`이 `draftPhotoKey`를 받을 수 있게 한다. 키가 `listings/<요청한 매물 ID>/`로 시작하고 저장소에 실제로 있으면 새로 올리지 않고 그 키를 쓴다. 등록하지 않고 버려진 초안 사진은 기존 `db:reconcile-photos`가 정리한다. 이때 초안이 지워지지 않도록 `--min-age-minutes 1440`(하루) 이상으로 실행하라고 문서에 적는다.

### 6.3 사용자 유형과 의도 판단

로그인 정보로 유형을 정하지 않고 **대화에서 판단한다.** 같은 사람이 빌리기도 하고 빌려주기도 하기 때문이다.

- 사진과 함께 온 말에서 의도를 고른다. 수리·고장(1), 정체·상태 문의(1), 판매(2), 대여 등록(2), 보험(요청 시).
- 모호하면 `offer_choices`로 묻는다: 「고장·수리 문의」, 「이게 뭔지 궁금해요」, 「팔고 싶어요」, 「빌려주고 싶어요」.

### 6.4 도구 (기존 도구에 추가)

| 도구 | 하는 일 | 데이터 |
| --- | --- | --- |
| `note_photo` | 사진에서 본 것을 기록한다: 기종, 추정 제조사·모델(카탈로그 ID 또는 null), 확신도, 보이는 상태(녹·파손·누유·타이어 마모 등) | 모델 판단 (추정 표기) |
| `lookup_machine_spec` | 카탈로그 모델 ID 또는 기종으로 제원과 미확인 항목을 조회한다 | `src/data/machine-specifications.js` |
| `get_repair_guide` | 기종과 증상으로 안전 자가점검 단계, 단계별 주의사항, 중단 조건을 반환한다 | `server/knowledge/repair-guides.js` |
| `find_repair_centers` | 지역(·제조사)으로 수리 창구를 찾는다 | `server/knowledge/repair-centers.js` + (설정 시) 공공데이터 임대사업소 API |
| `estimate_price` | 판매/대여, 모델 또는 기종으로 참고가 범위를 계산한다 | 등록 매물 통계 |
| `prepare_listing_draft` | 2의 판매·대여 초안을 확정한다: 제목, 소개글, 거래 방식, 추천 가격, 기종·모델. 로그인했으면 사진을 저장하고 키를 돌려준다 | 모델 작성 + 서버 저장 |
| `get_insurance_info` | 사용자 유형과 기종에 맞는 보험 개요와 가입처를 안내한다. **사용자가 요청했을 때만** 호출한다 | `server/knowledge/insurance.js` |
| `web_search` (선택) | `AI_WEB_SEARCH=1`일 때만 켠다. 지식 데이터에 없을 때만 쓰고, 결과는 "웹 검색 결과 · 확인 필요"로 출처와 함께 표시한다 | 공급자 내장 웹 검색 |

소개글은 모델이 사진 인식 결과, 제원, 사용자가 말한 사실만으로 쓴다. 게시자가 확인해야 하는 항목(연식, 사용시간, 포함 작업기)은 `[확인 필요]`로 남긴다.

### 6.5 지식 데이터 (A안)

모든 항목에 `source`(URL·제목)와 `checkedAt`을 붙인다. 테스트로 빠진 항목이 없는지 검사한다.

- **수리 가이드:** 기종군(엔진 기계: 관리기·트랙터·이앙기·콤바인·운반차 / 작업기 / 분무기) × 증상(시동 불량, 출력 저하·연기, 이상 소음·진동, 기름·물 샘, 작업기 미작동, 장기 보관 후 점검).
  - 단계는 "엔진 끄기·키 빼기·회전부 정지 확인"으로 시작하고, 눈으로 보고 손으로 만질 수 있는 점검만 넣는다. 연료량, 연료 밸브, 비상정지 스위치, 배터리 단자, 에어클리너, 엔진오일 레벨, 벨트·체인 이물질 같은 것이다.
  - 각 가이드에 "즉시 중단하고 전문가에게" 조건을 둔다. 연료 냄새·누유, 타는 냄새, 금속성 굉음, 유압유 분출, 부상 같은 경우다.
  - 근거는 제조사 취급설명서와 농촌진흥청·농기계 안전 자료다.
- **수리센터:** 영양군 농업기술센터(농기계 임대·수리), 지역 농협 농기계 수리센터, 카탈로그 제조사(대동, 아세아텍, 얀마, 혼다, 강농, 두루기계통상)의 A/S 대표번호와 공식 사이트.
  - 공식 출처에서 확인되지 않은 번호는 넣지 않는다.
  - `DATA_GO_KR_SERVICE_KEY`가 있으면 임대사업소 API 결과를 덧붙인다.
- **보험:** 농기계종합보험(정책보험)의 대상 기종, 보장 개요, 국가·지자체 보조 여부, 가입처(지역 농협)를 넣는다. 빌려주는 사람과 빌리는 사람이 각각 확인할 점(대여 중 사고 책임, 약관 확인)도 넣는다. 금액은 확정하지 않는다.

### 6.6 가격 추천 규칙

- 같은 모델 ID → 같은 기종 순으로 등록 매물을 찾는다. 판매는 `total`, 대여는 하루 `day` 가격으로 중앙값과 범위(최솟값~최댓값), 건수를 계산한다.
- 상태에 따른 보정은 하지 않는다.
- 비교 매물이 3건 미만이면 "근거가 적음"이라고 밝힌다. 비교 매물이 없으면 가격을 지어내지 않고 직접 정하도록 안내한다.
- 결과에는 항상 "플랫폼 등록 매물 기준 참고가, 실제 시세와 다를 수 있음"을 붙인다.

### 6.7 모델·설정

- `ZAI_MODEL` 기본값을 `glm-5.3`으로 바꾸고, `ZAI_VISION_MODEL`을 새로 둔다(기본 `glm-5.3-flash`). 이미지가 있는 호출에만 비전 모델을 쓴다.
- Z.ai 이미지 형식: `content: [{type:"text"}, {type:"image_url", image_url:{url:"data:..."}}]`
- Anthropic 이미지 형식: `{type:"image", source:{type:"base64", media_type, data}}`
- 둘 사이의 변환은 `server/llm.js`가 맡는다.
- `AI_WEB_SEARCH=1`: B안 켜기(기본 꺼짐).

### 6.8 시스템 지시 추가 (요지)

- 사진 판단은 "사진으로 보면 ~로 보여요"처럼 추정으로 말한다. 확신이 낮으면 확인 질문을 한다.
- 수리는 `get_repair_guide`에 있는 단계만 안내한다. 가이드에 없는 분해·정비는 안내하지 않고 수리센터로 연결한다.
- 전화번호와 사이트는 `find_repair_centers` 결과만 쓴다.
- 보험은 사용자가 먼저 물었을 때만 다룬다.
- 시니어를 위해 짧은 문장을 쓰고, 단계는 번호를 붙여 3~5개로 줄이고, 어려운 용어는 쉬운 말로 풀어 쓴다.

## 7. 테스트

- **단위 테스트:** 이미지 검증·축소 거부, 공급자별 이미지 블록 변환, 비전 모델 선택, 가격 계산(중앙값, 근거 부족, 비교 매물 없음), 수리센터 검색, 보험 도구가 요청 없이 호출되지 않게 하는 지시, 대화 기록에 사진이 남지 않는지.
- **통합 테스트:** 로그인한 2의 초안 사진 저장 → `draftPhotoKey`로 매물 등록 시 같은 키 사용, 다른 매물 ID의 키는 거부, 비로그인은 저장하지 않음.
- **지식 데이터 검사:** 모든 항목에 출처와 확인일이 있는지, 전화번호 형식, 위험 단어(분해·해체 등)가 자가점검 단계에 없는지.
- **브라우저 확인:** 📷로 사진 첨부 → 미리보기 → 전송 → 수리센터 카드의 전화·사이트 버튼, 소개글 복사, 「이 내용으로 매물 등록하기」로 등록 화면이 채워져 열리는지.
