# Claude 최종 교차 확인 — R1~R6 (라운드 2)

- 범위: `coordinator-resolution.md`의 R1~R6만. 새 코드 조사 없음, 수용된 결정은 재론하지 않음.
- 모델 근거: **실행 근거**는 조정자가 밝힌 `claude --model claude-fable-5-2 --effort high`. **내부 확인**은 세션 시스템 정보의 모델 ID `claude-fable-5-2`까지이며, effort 값은 세션 안에서 볼 수 없다. 불일치 정황은 없다.

| | 판정 | 남은 것 |
|---|---|---|
| R1 | 동의 | 없음 |
| R2 | 동의 | 경계 규칙 2개 명시 |
| R3 | 동의(목표) | 서버 재인코딩의 의존성 결정 1건 |
| R4 | 동의 | 첫 릴리스의 쓰기 동결 수단 |
| R5 | 동의 | 환경 표식 최초 생성 절차 |
| R6 | 부분 동의 | 읽기 잠금은 불필요 — 반례와 대안 제시 |

## R1 — 동의

1차 리뷰의 "운영에 옮길 업무 데이터가 없다"는 **b6a90b0 코드에서 추론한 것**이지 배포 상태를 확인한 것이 아니다. 철회하고 R1 문구로 대체한다. 배포 커밋, 실제 DB 스키마·행 수, 기존 계정, SQLite 파일은 미검증 재고로 두고, 추가 전용 마이그레이션은 실제 DB 확인 뒤에 확정한다.

## R2 — 동의

- 1차에서 제안한 날짜 기준 부분 UNIQUE는 철회한다. 중복 제출 방지는 클라이언트 생성 UUID가 맡는다.
- 최소 구현: 클라이언트 UUID를 **리소스 PK로 그대로** 쓴다. `INSERT … ON CONFLICT (id) DO NOTHING` 뒤 기존 행을 읽어, 행위자와 페이로드가 같으면 원래 결과를 반환하고, 다르면 내용을 노출하지 않는 409를 준다. 별도 컬럼이나 멱등 테이블이 필요 없고, PK + 행위자 비교가 "행위자 범위 유일성"을 충족한다.
- 승인 재시도 성공 반환, 매물 수정·소프트 삭제와의 직렬화(셋 다 매물 행 `FOR UPDATE`부터), 겹치는 대기 요청 유지에 동의한다. 자동 거절 제안은 철회한다. 앞선 승인이 취소되면 다시 승인할 수 있다는 장점이 더 크다.
- 명시가 필요한 경계 2개:
  1. **날짜 경계.** 현재 화면은 시작일=오늘을 허용한다. 승인 거부 조건은 `start_date < 오늘(Asia/Seoul)`, 승인 건 취소 허용 조건은 `오늘 < start_date`로 고정할 것.
  2. **파생 상태 표시.** 대기 요청을 남겨두면 "기간 충돌로 승인 불가"와 "시작일 경과"를 요청자·소유자 화면이 파생 표시해야 막다른 길이 되지 않는다. 소유자 대기 배지도 이 둘을 빼고 세어야 영구히 부풀지 않는다.

## R3 — 목표 동의, 구현 선택 1건

객체 키 저장(URL 파생), 서버 생성 불변 키, 즉시 정리 + 수동 대조 명령, DB 커밋 후에만 이전 객체 삭제, 모호한 커밋에서 삭제 금지에 모두 동의한다. 클라이언트 canvas가 보안 경계가 아니라는 점도 맞다.

- 키는 **시도마다 고유**해야 한다(예: `listings/{listingId}/{난수}`). 같은 UUID로 동시에 재시도한 두 요청 중 진 쪽이 자기 객체를 지워도 참조된 객체를 건드리지 않는다. R2의 재시도는 저장소에 쓰기 전에 기존 행을 먼저 확인한다.
- 대조 명령의 "참조됨"에는 `removed` 매물도 포함한다(요청·대화 이력이 참조).
- **결정 필요:** 서버 재인코딩은 이미지 라이브러리(통상 네이티브 의존성)가 새로 필요하다. 대상 런타임에서의 동작은 미검증이다. 의존성을 받지 않는다면 최소 대안은 **"재인코딩 대신 거부"**다. 클라이언트 canvas 재인코딩을 기본 경로로 두고, 서버는 매직 바이트·크기·헤더상의 픽셀 치수와 함께 메타데이터 세그먼트(JPEG APP1, PNG eXIf, WebP EXIF 플래그) 존재 여부를 검사해 있으면 거부한다. 정상 클라이언트는 항상 통과하고 보장은 서버가 강제한다. 의존성을 받는다면 재인코딩이 더 낫다.

## R4 — 동의

1차의 "롤백 = 이전 배포 재승격"은 **첫 실쓰기 이전에만** 유효하다는 한정으로 고친다. 이후에는 재배포만으로 서비스 정합성이 복구된다고 주장하지 않는다.

- 구체적 귀결: **첫 릴리스에는 "호환되는 이전 서버 기반 빌드"가 존재하지 않는다.** 실쓰기 이후 선택지는 쓰기 동결 + 전진 수정뿐이므로 동결 수단이 출시 시점에 이미 있어야 한다.
- 최소 수단: `app_meta`의 `writes_frozen` 값을 공용 변경 미들웨어가 확인해 503을 반환한다. 환경 변수 방식은 반영에 재배포가 필요할 수 있어 권하지 않는다(Vercel 동작은 미검증).
- RPO는 제공자의 백업·시점 복구 주기에 달려 있다(미검증). 수치를 기록할 것.

## R5 — 동의

체크섬 유지에 동의한다(1차의 "생략 가능"은 약한 선호였다). 빌드 단계 실행 선택지는 철회한다. 마이그레이션은 빌드·런타임과 분리된 명시 명령으로, 배포 전에 CI 또는 수동으로 실행한다.

- `BETTER_AUTH_URL` 정정에 동의한다. 정확한 규칙은 "Preview가 **운영의 값을 상속하지 않을 것**"이다. 미설정 또는 preview 자체의 고정 호스트 둘 다 가능하며, 실제 호스트·쿠키 동작으로 확인한다.
- 미결 1건: 환경 표식의 **최초 생성**. 운영 DB에는 Better Auth 테이블만 있고 `app_meta`가 없다. 일회성 명시 명령(`init --environment <값>`, 추가 전용)이 필요하고, 표식이 없는 DB에는 마이그레이션·시드가 실행을 거부해야 한다. 대상 확인 출력은 호스트와 DB 이름까지만 표시한다.
- `btree_gist`·풀링 확인과 실제 마이그레이션 기준 `user.id` 타입 검증에 동의한다.

## R6 — 부분 동의

동의: UUID `after_id`를 순서 있는 페이지네이션이라 부르지 않는다. 메시지는 멱등용 클라이언트 UUID와 순서용 증가 `seq`를 따로 둔다. 초기 이력은 최근 N건, 이전 페이지는 `seq < before`. 브라우저 자동화 3종(계정 전환 격리, 네트워크 실패 시 거짓 성공 없음, 세션 만료·폼 복구)을 유지한다 — API 테스트로 프런트 캐시·지연 응답을 증명할 수 없다는 지적이 맞고, 1차의 축소 제안은 철회한다. 해피패스 포함 4개 안팎으로 묶는다. 브라우저 자동화 도구는 새 개발 의존성이므로 명시 결정으로 기록할 것.

**이견: 읽기 쪽 대화 잠금은 불필요하다.**

- 반례(비용): 폴링 조회가 몇 초마다 대화 행을 잠그면 전송 트랜잭션과 서로 대기한다. 얻는 보장은 없다.
- 근거: 쓰기가 "대화 행 `FOR UPDATE` → 같은 트랜잭션에서 INSERT(이때 `seq` 할당)"를 지키면, `seq` 12는 11을 쓴 트랜잭션이 끝난 뒤에만 할당된다. 따라서 어떤 스냅숏이 12를 본다면 11은 이미 커밋되었거나 영원히 존재하지 않는다. 잠금 없는 단일 SELECT로도 낮은 번호를 건너뛸 수 없다.
- 최소 대안: 쓰기만 직렬화하고, 읽기는 잠금 없이 `WHERE conversation_id = $1 AND seq > $after ORDER BY seq LIMIT n`.
- 전제 두 가지를 문서에 고정: `seq`를 잠금 획득 **전에** 미리 뽑지 않는다. 대화 생성(`ON CONFLICT DO NOTHING`)도 같은 트랜잭션에서 잠금 뒤 INSERT 한다.

## 미결 요약 (조정자 결정)

1. R6 — 읽기 잠금 제거 수용 여부.
2. R3 — 서버 재인코딩(새 의존성) 대 메타데이터 거부 검사.
3. R4 — 출시 시점 쓰기 동결 수단 포함 여부.
4. R5 — 환경 표식 최초 생성 명령.
5. R2 — 날짜 경계와 파생 상태·배지 규칙 문구.

그 외 R1~R6 내용은 모두 동의한다.
