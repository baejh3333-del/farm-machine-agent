# 전국 지도·실거리·날씨 연결 설계

- 작성일: 2026-11-15
- 상태: 승인 대기

## 1. 의도

지금 화면의 "거리"는 영양군 네 읍·면 사이의 예시 숫자(`src/data/farm-machines.js`의 `distanceKm`)이고 지도는 없다. PRD의 P0 항목인 F01(지역 선택), F03(지도·거리 표시)이 비어 있어서 제품의 핵심 가치인 "가까운 농기계 찾기"를 보여줄 수 없다.

이번 작업으로 다음을 할 수 있게 한다.

- 전국 지도에서 매물 위치를 본다.
- 내 위치에서 매물까지의 직선거리를 실제 좌표로 계산한다.
- 대여 희망일의 날씨 예보를 보고 작업 날짜를 고른다.

홍천에서 데모 시연을 하므로, 홍천과 그 주변에서 매물이 촘촘하게 잘 보여야 한다.

## 2. 목표 / 하지 않는 것 / 실패 조건

**목표**

1. 검색 결과에 목록/지도 전환을 두고, 지도에 현재 필터가 적용된 매물을 마커로 표시한다.
2. 매물마다 좌표를 저장하고, 거리 표시·거리순 정렬·반경 필터가 그 좌표로 동작한다.
3. 예시 매물 100건에 전국 단위의 가짜 좌표를 넣고, 홍천 근처에 밀집시킨다.
4. 새 매물을 등록할 때 위치를 지정할 수 있다.
5. 대여 희망일과 AI 추천 문구에 날씨 예보를 한 줄로 보여준다.

**하지 않는 것**

- 도로 기준 이동 거리·경로 안내 (PRD F03: 별도 서비스 연동 전까지 표시하지 않음)
- 주소 검색, 정확한 주소 저장
- 3일을 넘는 중기예보, 날씨 전용 화면
- 사용자 위치의 서버 저장·추적

**실패 조건 (동작하더라도 실패로 본다)**

- 매물의 정확한 보관 위치가 드러난다.
- 가짜 위치가 실제 매물 위치처럼 보인다.
- 지도·날씨 키가 없거나 외부 API가 죽었을 때 목록·검색·등록이 깨진다.
- API 키가 저장소에 커밋된다.

## 3. 제약

- 프런트는 프레임워크 없는 순수 JS(`src/main.js` 약 3,000줄), 서버는 Vercel 함수(`api/`) + `server/` 모듈, DB는 PostgreSQL(테스트는 PGlite).
- `npm run check`는 외부 키와 네트워크 없이 통과해야 한다.
- 스키마 변경은 `server/migrations/`에 번호를 이어서 추가한다(현재 0002까지).
- 이 작업은 PostgreSQL 재구축(`feature/db-rebuild` 계열)이 반영된 코드 위에서 시작한다. 아직 `main`에 머지되지 않았으므로 머지 후 새 브랜치에서 진행한다.

## 4. 검토한 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| A. 읍·면 좌표 표 | 지역 이름별 대표 좌표를 코드에 두고 매물은 이름만 저장 | 전국 단위에서는 표가 수천 건이 되고, 같은 지역 매물이 한 점에 겹친다. 탈락 |
| **B. 매물별 좌표 저장** | 매물 테이블에 위도·경도를 저장하고 지도에서 위치를 찍어 등록 | **선택.** 전국 단위와 가짜 위치 배치를 그대로 표현할 수 있다 |
| C. 리 단위 선택 | 행정구역을 리까지 골라 리 대표 좌표 사용 | 전국 리 좌표 데이터 준비 부담이 크고 B보다 얻는 것이 없다. 탈락 |

사용자가 "전국 단위, 가짜 위치를 정해 지도에서 보기"를 요구했으므로 B로 확정했다.

## 5. 설계

### 5.1 외부 서비스 (작성자 결정)

| 용도 | 선택 | 이유 |
|---|---|---|
| 지도 | 카카오맵 JavaScript SDK (마커 묶음·좌표→행정구역 변환 라이브러리 포함) | 국내 농촌 지역 지도가 상세하고 무료 한도 안에서 충분 |
| 날씨 | 기상청 단기예보 (공공데이터포털 `getVilageFcst`) | 국내 공식 예보, 무료 |

- 카카오 키는 브라우저에 노출되는 구조이므로 카카오 개발자 콘솔의 도메인 제한으로 보호한다. 운영 도메인, Vercel 프리뷰 도메인, `localhost:3000`을 등록해야 한다.
- 기상청 키는 서버 환경 변수로만 두고 브라우저에 내려보내지 않는다.
- 환경 변수 이름은 `KAKAO_MAP_APP_KEY`, `KMA_SERVICE_KEY`로 하고 `.env.example`에 추가한다.

### 5.2 좌표 저장

- 마이그레이션 `0003`으로 `listings`에 `lat`, `lng`(DOUBLE PRECISION, NULL 허용)를 추가한다. 값이 있으면 대한민국 범위(위도 33~39, 경도 124~132) 안이어야 한다.
- **위치 보호:** 서버는 좌표를 소수 둘째 자리(약 1km)로 반올림해 저장한다. 원본 좌표는 어디에도 남기지 않는다. API는 반올림된 값만 돌려준다.
- `region`은 지금처럼 문자열로 유지하되 "강원 홍천군 서석면"처럼 시·도부터 적는다(40자 제한 안).
- 좌표가 없는 기존 매물은 지도에 나오지 않고 거리는 표시하지 않는다. 영양군 네 지역 이름을 가진 기존 비예시 매물은 마이그레이션에서 해당 읍·면 대표 좌표로 채운다.

### 5.3 거리

- 클라이언트와 서버가 함께 쓰는 하버사인 직선거리 함수 하나를 둔다. 기존 `distanceKm(from, to, itemId)`와 난수 캐시는 삭제한다.
- 거리 표시(목록 카드, 상세), 거리순 정렬, 반경 필터(`src/main.js`의 `matches`, `compareListings`), 서버 추천 후보 정렬(`server/agent.js`)이 모두 이 함수를 쓴다.
- 화면에는 "직선거리"임을 표기한다.
- 좌표가 없는 매물은 거리순 정렬에서 맨 뒤로 가고, 반경 필터를 켜면 제외된다.
- `agent/` 폴더의 Eve 실험 파일은 현재 화면과 별개이므로 이번 작업에서 건드리지 않는다.

### 5.4 내 위치

- 기본값은 홍천읍 중심(홍천군청 부근, 대략 북위 37.70 / 동경 127.89. 구현 시 실제 좌표로 확인)이다.
- "현재 위치 사용"을 누르면 브라우저 위치 권한을 요청한다. 거부하거나 실패하면 지도에서 직접 찍어 정한다(PRD F01).
- 내 위치는 지금의 `state.region`처럼 브라우저에만 저장한다. 서버에는 추천·날씨 요청 때 좌표만 전달하고 저장하지 않는다.
- 저장된 예전 값("영양읍" 등)은 기본값으로 대체한다.

### 5.5 지도 화면

- 검색 결과 영역에 목록/지도 전환을 둔다. 지도는 목록과 같은 필터·검색어 결과를 보여준다.
- 처음 열면 내 위치를 중심으로 홍천군과 인접 시·군이 한 화면에 들어오는 배율로 시작한다.
- 축소하면 마커를 숫자 묶음으로 합치고, 확대하면 개별 마커로 풀린다.
- 마커를 누르면 해당 매물의 요약 카드가 뜨고, 카드를 누르면 기존 상세 화면으로 간다.
- 예시 매물(`is_demo`)은 마커 카드와 상세에 "예시 위치"로 표시한다.
- 카카오 키가 없거나 SDK를 못 불러오면 지도 전환 자리에 안내 문구만 보이고, 목록·거리·등록은 그대로 동작한다.

```
[ 목록 | 지도 ]                     총 37대 · 거리순
┌────────────────────────────────────────────┐
│            (12)        ● 화촌면             │
│   춘천                                      │
│          ◎ 내 위치(홍천읍)     ● ●  서석면   │
│     ●                                       │
│              (5) 횡성                        │
└────────────────────────────────────────────┘
┌ 대동 관리기 8마력 · 예시 위치 ───────────────┐
│ 강원 홍천군 화촌면 · 직선 7.2km · 45,000원/일 │
└────────────────────────────────────────────┘
```

### 5.6 매물 등록 시 위치

- 등록·수정 화면의 읍·면 선택 목록(`editRegion`)을 지도 위치 지정으로 바꾼다. 지도를 눌러 핀을 놓거나 "현재 위치 사용"을 쓴다.
- 핀 좌표를 카카오의 좌표→행정구역 변환으로 "시·도 시·군·구 읍·면·동" 이름으로 바꿔 `region`에 넣는다.
- 화면에 "약 1km 단위로 흐리게 저장되며 정확한 주소는 공개되지 않습니다"를 안내한다.
- 서버(`server/listings-service.js`)는 좌표 범위를 검증하고 반올림해 저장한다. 클라이언트가 보낸 좌표를 그대로 믿지 않는다.
- 카카오 SDK가 없을 때는 "현재 위치 사용"과 지역 이름 직접 입력으로 등록할 수 있어야 한다(테스트 환경 포함).

> 대화 중에는 "시·도 → 시·군·구 → 읍·면·동 선택"을 제안했으나, 전국 행정구역 좌표 표를 따로 관리할 필요가 없는 지도 지정 방식으로 바꿨다. 작성자 결정이다.

### 5.7 예시 매물의 가짜 위치

- `server/listing-seed.js`의 100건에 좌표와 새 지역 이름을 넣는다. 영양군 지역은 모두 교체한다.
- 배치: 홍천군 10개 읍·면에 약 40건, 인접 시·군(춘천·횡성·인제·평창·양평)에 약 20건, 그 밖의 전국 농업 지역 시·군 약 20곳에 약 40건.
- 좌표는 고정값이거나 매물 ID로부터 결정적으로 계산한다. 다시 시드해도 위치가 바뀌지 않아야 한다(`Math.random` 금지).
- 좌표는 육지의 농경지 부근이어야 한다. 바다·호수·산 정상에 찍히지 않게 확인한다.
- 작물과 지역이 어긋나지 않게 한다(예: 벼 이앙기를 고랭지 내면에 몰아 두지 않는다).

### 5.8 날씨

- 새 함수 `GET /api/weather?lat=..&lng=..`를 추가한다. 서버가 위·경도를 기상청 격자 좌표로 바꿔 단기예보를 조회하고, 날짜별로 하늘 상태·강수확률·강수량·최저/최고기온·풍속을 정리해 돌려준다.
- 조회 위치는 **내 위치**(작업할 밭이 있는 곳)다. 매물 위치가 아니다. 작성자 결정이다.
- 예보 범위를 벗어난 날짜는 값 없이 돌려주고, 화면은 아무것도 표시하지 않는다.
- 같은 격자·같은 발표 시각의 예보는 한 번만 기상청에 요청하도록 캐시한다. 기존 호출 제한(`server/rate-limit.js`)을 이 함수에도 적용한다.
- 표시 위치는 두 곳이다.
  - 대여 날짜를 고르는 곳(날짜 필터, 대여 요청) 옆에 한 줄: `11/17(화) 흐리고 비 60% · 3~11℃`
  - AI 추천(`server/agent.js`): 희망일 예보를 프롬프트에 넣어 "비 예보가 있어 방제 작업은 하루 미루는 것이 좋습니다" 같은 안내가 나오게 한다. 예보 값은 API 결과만 쓰고, 값이 없으면 날씨를 언급하지 않게 한다.
- 키가 없거나 기상청이 응답하지 않으면 날씨 줄만 숨긴다. 추천·검색·대여 요청은 날씨와 무관하게 동작한다.

### 5.9 테스트

- 하버사인 거리, 좌표 반올림·범위 검증, 격자 좌표 변환, 예보 응답 정리(고정 응답 파일 사용)는 단위 테스트로 확인한다.
- 시드 100건 모두 유효한 좌표를 가지며 재실행해도 같은 값인지 확인한다.
- 키 없는 상태에서 목록·거리·등록이 동작하는 것을 기존 브라우저 테스트(`tests/browser-e2e.test.js`)에 추가한다.
- 실제 카카오·기상청 호출은 자동 테스트에 넣지 않고, 키를 넣은 로컬과 Vercel 프리뷰에서 손으로 확인한다.

## 6. 구현자에게 맡기는 것

- 카카오 키를 브라우저에 전달하는 방법(빌드 시 주입 또는 설정 응답). Vercel 함수 개수를 불필요하게 늘리지 않는다.
- 날씨 캐시 저장 위치(DB 테이블 또는 메모리)와 만료 규칙.
- 지도·날씨 코드의 파일 분리. `src/main.js`에 더 쌓지 말고 별도 모듈로 둔다.
- 마커·묶음 디자인, 지도 높이, 모바일 배치.
- 구현 순서. 권장: 좌표·거리 → 시드 → 지도 표시 → 등록 위치 지정 → 날씨.

## 7. 사용자 준비 사항

- 카카오 개발자 계정에서 앱을 만들고 JavaScript 키 발급, 사이트 도메인 등록.
- 공공데이터포털에서 "기상청_단기예보 조회서비스" 활용 신청 후 서비스 키 발급.
- 두 키를 `.env.local`과 Vercel 환경 변수에 직접 입력.
